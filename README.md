### `[01]` Methodology

```console
afaaq@sec:~$ ./engagement --phases
```

| Phase | What I do |
|---|---|
| **Recon** | Map the attack surface: subdomains, endpoints, parameters, technologies, exposed assets |
| **Enumeration** | Understand how the app works: auth flows, roles, object references, input handling |
| **Exploitation** | Validate each weakness with a minimal, safe proof of concept |
| **Impact analysis** | Show what an attacker gains: data exposure, account takeover, privilege escalation |
| **Reporting** | Clear reproduction steps, severity rationale, and actionable remediation |

---

### `[02]` Vulnerability Focus

| Class | What I look for |
|---|---|
| **XSS** | Unsanitized input reflected or stored in the DOM, context-specific payloads |
| **SQL Injection** | Injectable parameters, authentication bypass, data extraction paths |
| **IDOR / Access Control** | Predictable object IDs, missing authorization checks between users |
| **CSRF** | State-changing requests lacking anti-forgery protection |
| **SSRF** | Server-side requests an attacker can steer toward internal resources |
| **XXE** | XML parsers that accept external entities |
| **Info Disclosure** | Verbose errors, exposed files, leaked tokens and metadata |
| **Clickjacking** | Missing frame protections on sensitive actions |
